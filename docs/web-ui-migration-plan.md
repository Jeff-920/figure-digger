# fig-extract 网页改造方案（交给编码 AI）

日期：2026-10-24。本文只提供实施方案，不包含应用代码，也没有执行迁移、安装依赖或运行提取任务。

## 1. 目标与技术判断

后续修改限定在 `D:/WebPlotDigitizer-master/fig-extract/`。目标是参考用户截图，将 DIG 当前网页改成常规管理网页的实现方式与布局：顶部导航、标题工具栏、筛选区、任务表格、详情页。继续使用 DIG 自己的名称、字段和提取功能。

### GitHub 调研结论

已在 GitHub 搜索 `DChem`、`ChemLib`、`MechLib`、`Experimental Cases`、`Hierarchical Search Scope` 及其组合，没有找到能够与截图对应的公开实现。搜到的同名仓库 `vastencn/Dchem` 主要包含 PNG、SVG；抽查的 SVG 是化学内容，不能作为截图网站的源码证据，也不能据此判断框架。

从截图可见的导航、下拉框箭头、表格、徽章与图标形态看，**较像 Bootstrap 5 风格组件搭配 Font Awesome 图标**。这是外观推断，不能排除其他框架或定制 CSS。截图不能证明后端使用 Flask、Django 或其他包，也无法确认某个管理后台模板。

本方案的实施选型是 **Flask + Jinja2 + Bootstrap 5.3.8 + Font Awesome Free 6 系列**。其中 Flask 是针对本项目 Python 基础作出的工程选择，不是对原站后端的鉴定。若后续提供原站网址或源码，应以真实依赖为准；不要为了等待原站信息阻塞本方案的实施。

参考来源：

- [Bootstrap 官方仓库](https://github.com/twbs/bootstrap)：提供导航、表格、表单、徽章等网页组件。主分支目前面向 Bootstrap 6 开发，实施时固定使用已发布的 5.3.8，避免跟随主分支。
- [Bootstrap 5.3.8 下拉框样式源码](https://github.com/twbs/bootstrap/blob/v5.3.8/scss/forms/_form-select.scss)：可作为截图下拉框外观与实现方式的参考，不能作为原站实际使用该库的证明。
- [Flask 官方说明](https://github.com/pallets/flask/blob/main/README.md)：轻量 Python Web 框架，使用 Jinja 模板体系，适合复用当前 Python 工程。
- [Font Awesome 官方仓库](https://github.com/FortAwesome/Font-Awesome)：图标库；6 系列已进入 LTS。使用一个固定的 Free 6 正式版本即可，具体补丁版本在实现时记录。

### “同种原理”的实施含义

服务器通过 Flask 路由读取任务与结果，用 Jinja 输出普通 HTML，Bootstrap 负责组件样式，少量原生 JavaScript 处理日志轮询和必要的交互。提取任务在后台执行，浏览器通过 HTTP 查询状态。

这次应真正替换网页层，不继续依赖 Streamlit 的组件 DOM 和整页重跑机制。算法仍经现有 CLI 调用。无需新增 React、Vue、Vite、Tailwind、完整后台模板、前端状态库或 Node 构建过程。

## 3. 页面结构与截图对应关系

### 首页：任务结果列表

以任务列表作为首页，首次没有记录时提供清楚的空状态和“新建提取”按钮。

1. 顶部白色导航条：左侧 DIG 标识，中间保留“开始提取 / 任务结果 / 使用说明”三个原有功能名称，右侧可放已有密钥状态或设置入口。当前页面有选中状态。
2. 标题工具栏：左侧“任务结果”及一行简短说明；右侧是任务搜索框与“新建提取”按钮。
3. 白色筛选容器：标题“任务筛选”，右侧显示实际匹配任务数；下方三列分别为处理状态、读图方式、流程。
4. 主体为白色紧凑表格，按创建时间倒序；默认每页 25 条，服务端查询参数控制筛选、搜索与分页。

筛选项彼此独立，不模拟截图中反应器、燃料的层级关系。搜索覆盖文件名、任务 ID 和可获得的提取目标。筛选与翻页保留 URL 参数，刷新后状态可恢复。

建议表格字段：

| 字段 | 数据来源与显示原则 |
| --- | --- |
| 序号 | 当前分页的实际序号 |
| 任务 ID | 现有目录名，可短显并提供完整值 |
| 论文 / 文件 | 现有 `label`；长文件名截断并可查看全文 |
| 提取目标 | 新元数据的 `want`；旧记录可从已保存的参数数组读取 `--want`，没有则显示“全部数据图”或“未记录” |
| 流程 | 现有 `mode` |
| 读图方式 | 现有 `method` |
| 创建时间 | 新记录用明确时间字段，旧记录优先从任务 ID 推导，必要时回退目录时间 |
| 耗时 | 现有 `elapsed`；未结束时显示运行耗时 |
| 结果 | CSV、核对图等实际数量 |
| 状态 | 综合执行状态、提取结果及批量失败情况计算 |
| 操作 | 查看详情、已有结果下载 |

不要复制截图中的 Admin、用户登录、Data Matrix、编辑和删除图标。这些没有对应的现成功能，本次也不新增账户系统、数据矩阵或任务删除功能。

### 新建任务页

延续现有两栏信息结构，改用标准 HTML 表单和 Bootstrap 组件：

- 左栏为多 PDF 上传区、文件列表、页数与大小、提取目标、可选模板。
- 右栏为流程、读图方式、密钥输入、记忆密钥、已有密钥状态；高级参数收在一个折叠区域。
- 提交前给出本次任务摘要；成功提交后进入任务详情页。
- 页面刷新、切换折叠区域和修改控件不触发后台任务。只有提交表单才启动任务。
- 现有字段名称、顺序、默认值和限制尽量沿用；例如 DPI 300、批量并行数 2、OCR 交叉核对默认关闭。

### 任务详情页

顶部显示任务名、准确状态、时间与“返回任务结果”。运行中展示当前状态和日志尾部，结束后展示结果统计及下载。

保留五个结果标签：“图像核对 / 曲线数据 / 模板文件 / 报告 / 日志与配置”。图片可选文件并查看原尺寸；CSV 最多预览 200 行，下载包含全部数据。模板、报告和日志以转义后的可读文本展示并保留换行，原始文件仍可下载。无需为报告额外引入 Markdown 渲染与 HTML 清洗依赖。

文件选择可以通过同一详情页的查询参数完成，由服务器读取选中的预览文件，避免为每种预览另建接口。运行结束时只自动刷新一次详情内容；不要在用户选文件或查看图片时持续整页刷新。

## 5. 路由与数据流

建议维持以下有限接口；路由函数名由编码 AI 自定：

| 方法与路径 | 行为 |
| --- | --- |
| `GET /` | 读取历史记录，搜索、筛选、分页后渲染列表 |
| `GET /new` | 新建任务表单 |
| `POST /runs` | 接收 multipart 文件与参数，校验、落盘、入队，返回 303 跳转至详情 |
| `GET /runs/<run_id>` | 展示任务详情，查询参数指定当前标签或预览文件 |
| `GET /api/runs/<run_id>` | 返回状态、运行耗时、有限长度日志尾部及完成标记 |
| `GET /runs/<run_id>/files/<path:artifact_path>` | 根据允许的结果文件生成预览或下载响应 |
| `GET /runs/<run_id>/archive.zip` | 用户主动点击时生成并下载结果 ZIP |
| `POST /settings/api-key` | 明确保存输入的密钥 |
| `POST /settings/api-key/clear` | 清除本机保存的密钥 |
| `GET /help` | 使用说明 |

普通页面由 Jinja 输出。日志接口只在任务排队或运行期间每 1–2 秒查询一次，完成、失败、中断或离开页面后停止。短暂网络失败时降低查询频率并显示可恢复提示，不无限快速重试。

运行与打包期间按钮显示简短反馈；HTTP 错误在页面内显示，不使用浏览器弹窗。筛选无结果、任务无输出、下载不存在等状态应有明确文字和可用的下一步。

## 6. 后台任务与历史兼容

### 最小执行模型

使用一个进程内后台执行器，网页任务默认串行执行；每个批量任务仍通过现有 `--jobs` 控制其内部并行数。HTTP 服务保持可响应，浏览器关闭或刷新不终止任务。

复用 `RunOptions` 与 `build_command()`，继续以参数数组调用同一个 Python 解释器下的 `run.py`。不要在路由中重新拼装一套 CLI 参数，不使用 shell 命令字符串。Windows 继续使用隐藏子进程窗口的方式。

现有 `run_pipeline()` 中刷新 Streamlit 控件的部分去掉，子进程输出仍写入 `ui-run.log`。执行器只创建一次，关闭开发模式自动重载。不要引入 Celery、Redis、多服务或外部任务数据库。

提交流程采用 POST 后 303 跳转，避免刷新详情导致重复提交；提交按钮防止重复点击。不要为此搭建复杂的通用幂等框架。

### 元数据

保持原有 `label`、`mode`、`method`、`command`、`code`、`elapsed` 字段；新增少量必要字段：执行状态、创建/开始/结束时间、提取目标、读图方式与流程的稳定标识、结果计数摘要。时间使用带时区偏移的 ISO 格式。

新记录先保存 queued，再进入 running，最后记录 succeeded 或 failed。进程结束后调用现有结果收集函数生成摘要。元数据通过临时文件加原子替换保存，避免列表读到半份 JSON。

服务启动时将遗留的 queued/running 记录识别为 interrupted，提示任务中断；不要自动重新调用模型。当前状态不支持断点续跑，不做恢复队列或自动重试系统。

旧 `ui-run.json` 缺少新字段时仍能展示，不批量重写旧任务，也不移动已有产物。旧记录无法可靠恢复的信息显示“未记录”，不要猜造。新任务结束时写入结果计数；轮询只查当前任务与日志尾部，避免每次递归扫描所有历史输出。

### 状态语义

执行状态与业务结果分开计算：

- 排队中、运行中、已中断、处理失败。
- 仅分析完成：待确认坐标。
- CLI 正常退出但没有 CSV 和模板：未提取到数据。
- 有提取结果：提取完成，待核对数据。
- `batch_summary.json` 存在部分论文错误：明确显示部分失败，即使总体退出码为 0。

复用 `result_status()`、`batch_failures()` 与 `collect_artifacts()` 的现有含义。不要因为退出码为 0 就显示所有论文成功，也不要给尚未人工核对的结果显示“已核对”。

## 7. 功能边界与必要处理

### 表单规则

保留现有约束，关键规则由服务器在入队前确认，浏览器提示只负责帮助输入：

- 至少一份可读取 PDF；重复文件名仍安全重命名。
- 页码从 1 开始，沿用逗号列表格式，并检查是否超出对应 PDF 页数。
- 仅分析模式只接受一篇 PDF。
- 本地 OCR 只接受当前支持的纯图号需求；内容、工况和子图条件需要视觉模型。
- 模板导出需要视觉模型与自动提取。
- DPI 和并行数限定在现有控件允许范围，布尔参数规范化后传入 `RunOptions`。
- 沿用模型名、接口地址、OCR 默认值与自动轴范围开关的语义。

不在本次重新设计命令行规则或扩展输入类型。

### 密钥与文件

沿用 `save_api_key()`、`clear_saved_api_key()` 及当前 CLI 的密钥读取优先级。新密钥勾选“记住”后只在明确保存或提交任务时写入文件；未勾选时仅供当前任务使用。不要在读取页面时触发写入。

密钥输入框始终不回填已保存值，页面只返回是否可用；密钥不进入 URL、元数据、实际命令数组、日志和下载包。子进程通过环境变量接收当前任务密钥，禁止输出整个环境或表单请求体。

任务 ID 只对应现有工作目录中的任务；文件解析为绝对路径后确认仍位于该任务允许的输出目录，并与收集到的产物核对。上传文件名继续经 `safe_filename()` 处理。客户端不提交任意服务器路径或执行命令。

CSV、模板、报告和文件名由模板自动转义；日志追加到页面时使用文本方式。核对图继续只取 `verify/` 的叠加结果，不把被排除的候选图、裁剪图或诊断图混入核对列表。

ZIP 继续按现有输出目录规则打包，在用户点击时生成即可；不在每次轮询、列表加载或页面刷新时打包。

## 8. 编码顺序与清洁要求

1. 复用现有函数，先将任务执行与历史读取从 Streamlit 控件中解开，保持 CLI 行为不变。
2. 实现 Flask 应用、任务提交与状态记录，确保从上传到结果访问的流程连通。
3. 接入 Bootstrap 公共模板，完成列表、表单、详情与说明页，再集中调整主题样式。
4. 接入密钥操作、文件预览和下载，补全空状态、部分失败与中断状态。
5. 替换网页依赖和启动说明，完成有限验证后清除旧 Streamlit 页面代码及无用依赖。

最终只保留一个正式网页入口，建议在 `fig-extract` 中用 `python app.py` 启动，默认监听 `127.0.0.1:8501`；通过一个简单参数或环境变量允许调整端口。保留原有 CLI 的所有用法。

代码要求：

- Python 负责业务与文件处理，Jinja 负责结构，CSS 负责样式，JavaScript 负责少量交互。
- 不将整页 HTML/CSS/JS 拼在 Python 字符串中，不继续通过内部 DOM 选择器覆盖 Streamlit。
- 不保留 `app_old.py`、第二套默认首页、重复状态计算、重复 CLI 构造或一串补丁式样式覆盖。
